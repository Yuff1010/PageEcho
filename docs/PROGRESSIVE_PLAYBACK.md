# 在线首播与未完成缓存

`0.38.0-dev.1` 为首次收听的在线 MP3 增加顺序缓冲：主进程接收一个完整 GET 响应，确认格式并写入至少 32 KiB 后，即可让同一个播放器读取已落盘部分。无需等整个文件下载后再开播。来源返回未知长度、已有完整音频身份、存在上次未完成的位置，或用户选择“先准备字幕再播放”时，继续走完整缓存路径。

## 身份和保存

临时播放地址为不透明的 `readlisten://app/stream/<sessionId>`。网页地址、签名及请求头不会交给 renderer。未完成的章节 `contentHash` 仍为空，不创建 `StoredAudio`，不提交给识别、原文对齐、书签或离线完成统计。

下载器只使用本次被接受的单个 200 响应，不用多个远端 Range 拼接实体，因此不要求来源提供 ETag。本机播放器的 GET／HEAD／单 Range 由独立只读文件句柄处理：每次最多读取 64 KiB，尚未落盘的区间等待下载；非法／多 Range 拒绝，全局最多 16 个 reader，每次缺数等待最多 120 秒。远处跳转可能等待下载到目标位置，不承诺即时跳转。

完整下载仍经过长度、MP3 前缀、fsync、SHA-256、rename 和数据库事务后，才成为可供字幕使用的完整音频。主进程将当前会话移交为真实哈希；renderer 更新身份，保留原 audio 元素、地址和时间，不重新 load。自动字幕只在此后按原设置开始，手动模式不会自动改为生成。

临时位置单独保存在 schema 18 的 `online_pending_progress`，包括 Main 产生的已落盘前缀字节数、SHA-256、总长度和会话。这个摘要不是完整音频哈希。播放中的保存只使用最近确认已有缓冲数据的位置，拖到未缓存远处后立即暂停／退出，不把尚未取得数据的目标当作已听位置。

重启后有临时位置的集会保守地先完整下载，核对上次前缀和总长度，再恢复；已有后台完整缓存也必须核对。不同前缀／长度的新实体从零开始，不将旧位置套到新录音。事务完成只移交该集位置，不覆盖用户后来切换的当前集、倍速或音量。活动 lease 不进入备份；旧请求、晚到结果和关闭都按 sessionId／requestId 隔离。

## 取消与界面

- 暂停声音会保留当前下载；切集、停止或退出取消所属下载并等待文件流收尾。
- 已确认的位置和前缀证明保留，未提交的本次 `.part` 由所属下载器收尾，不作为离线文件或模型输入。
- 缓存状态复用播放器的字幕状态图标及 Tooltip，不增加常驻状态栏。临时阅读页使用同一个 `ReaderToolbar`、标题几何和 `ReaderDock`；完整音频准备好后进入原有字幕流程。
- 长度不符、格式错误、磁盘／数据库失败不能生成可播放的完整记录。失败提示可见，重新播放会重新获取；旧字幕及人工修改保持版本身份。

## 验证与限制

真实 Chromium 与 stock Main 的门控合成 MP3 验证：服务端保留尾部、只发送 32,768／80,474 字节时，audio 已开始播放；完整提交后保持元素、地址、播放位置和阅读工具栏几何。另验证了暂停继续下载、远处 seek 立即退出、前缀变化后重启归零、状态 IPC 延迟、迟到源释放、创建中连续取消及备份恢复。

对当前听十三公开样本做了一次成功的自然网速验证：3,209,629 字节 MP3 正常播放、完整摘要及重启恢复通过；首次观察声音时下载已经完成，**本次没有证明实站的提前出声或平均提速**。门控结果只证明实现具备渐进播放能力，不代表所有 MP3、网络或来源都更快。

部分来源已改变媒体域名；未验证的地址仍被精确 allowlist 拒绝，没有为提速放宽到通配域名。未知长度、完整身份、续听校验及字幕预备模式的回退属于兼容边界。模块职责、当前报告与产物见 [0.38 版本记录](releases/0.38.0-dev.1.md)。
