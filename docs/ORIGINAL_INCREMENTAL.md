# 原文自动增量匹配

## 行为与触发

同一本书导入 TXT / EPUB 原文后，新生成或新导入的转写片段会自动匹配原文，不必等整集识别完成，也不必逐块点击“重新匹配”。原有手动匹配、搜索、人工留空与同步点校正入口继续可用。

自动调度由 `AutomaticOriginals` 管理，按 `episodeId + audioHash` 合并请求：

- 文稿成功写入后，`LibraryStore.writeTranscript` 只发送原文变更通知；匹配不参与文稿或音频的写入事务。
- 导入原文后调度当前目标；读取原文状态也会请求补齐，便于打开未处理过的一集。
- 启动时查询最近最多 8 个同时具有原文与文稿的目标，补齐持久化的未完成工作。
- 75 ms 合并突发通知，执行时读取最新文稿，不依赖通知携带的旧快照。
- 自动提交成功后复用现有 `transcriptionChanged` 通知。原文视图会刷新匹配，即使文稿修订号没有再次变化。

导入新原文只主动调度当前目标，并不立即重跑这本书的所有历史分集。其他分集可由后续文稿变化、打开原文、启动补齐触发。

## 增量批次与非连续覆盖

`createIncrementalPlan` 比较源片段 ID、文字和原始 ASR 起止时间；匹配规则版本与文稿身份也参与复用判断。已完成且来源可证明相同的自动映射继续复用。新片段、改变的片段和缺少可复用依据的自动映射才进入本轮目标。

每次最多处理 128 个待匹配片段。每个目标可带前后各 3 个同一 coverage 区间内的邻片段作为上下文，相邻上下文合并；工作线程只返回本轮目标 ID 的结果。不会因新增一个块而对整集再次全文匹配。

原文检索仍使用整本书索引。自动工作线程按原文版本缓存一个检索器；同一版本的后续批次只发送增量片段。原文存储层也只缓存一个已解析版本，切换版本会替换缓存。重启后索引在需要时重新建立，并非持久化磁盘索引。

先识别 60–90 秒、再补 0–30 秒等非连续结果可以分别匹配。邻句上下文不跨越未覆盖的音频空洞；后续补齐缺口只处理新来源，已有映射和人工锚点继续保留。已确认的左右原文位置约束新候选，人工留空会断开邻句组合。

`pendingSegments` 表示当前文稿仍未完成匹配检查的来源数，不表示所有已处理片段都有确定映射。重复、插话、缺失或低把握内容仍可保持空缺。

## 人工校正与旧来源

人工确认的原文位置、人工留空及人工起止时间始终优先于新自动结果。识别重分组导致旧片段 ID 消失时，这些记录也保留；与它们重叠的自动记录不覆盖人工决定。

每条匹配可保存独立的原始识别时间 `source`，不会用人工修改后的显示时间冒充 ASR 来源。对齐记录另有 `sources` 清单，记录完成匹配检查的片段来源。来源状态用于解释保留记录：

| 状态       | 含义与界面                                                           |
| ---------- | -------------------------------------------------------------------- |
| `current`  | 与当前识别来源相符；人工时间仍按人工选择显示。                       |
| `retained` | 原识别来源已改变或消失，保留此前人工校正；界面提示核对原文与同步点。 |
| `legacy`   | 旧人工记录没有保存原始识别依据，保守保留并明确提示旧来源。           |

旧人工记录不会标成当前自动结果。校对区仍可进入人工修正；跟随旧人工位置时提示“沿用旧人工同步点”。换用不同原文版本时，对齐按原文版本独立存储，不会把旧版本的句号位置直接套到新版原文上。

当前文稿比对齐更新时，后端只允许对来源仍可证明一致的记录直接校正；否则返回版本冲突。重新匹配和人工校正仍有各自的修订号检查。

## 并发、退出与资源边界

匹配计划固定原文 ID、文稿 ID/修订号、对齐修订号。提交前同时比较这些值；识别继续新增块、用户修改原文或人工保存后，旧响应不能覆盖新状态。主线程检查和写入之间没有异步等待。

手动整集匹配期间暂停同一目标的自动任务，必要时终止正在执行的自动工作线程；手动结束后再调度增量补齐。切集使用独立目标，界面按目标重新建立状态，并用请求序号忽略迟到的读取或手动响应。后台刷新不会重建现有校正编辑器，因此未提交的时间、搜索文字和局部错误提示保留。

每轮最多执行 16 次计划，然后让出 150 ms；仍有成功进展的工作会继续，不需要用户刷新。活动与等待目标合计最多 8 个，已取得进展的任务在让出期间仍受保护，不被新目标挤掉。压力过大时尚未开始的请求可能被替换；它们可由后续事件或打开原文重新调度。当前没有全书库持久化自动任务队列。

一次轮次内同一目标最多重试 2 次并发冲突；超过预算或发生实际处理错误后，当前失败快照停止自动重试。新的来源/修订可触发后续处理，手动匹配入口仍可用。失败不阻断播放、不删除原文或已有对齐；来源不再适用的旧对齐仍遵循现有 stale 显示规则。没有内容变化的自动结果不会增加修订或发送更新通知，避免状态读取与通知循环。

自动工作线程每次请求限制 60 秒、堆内存上限 512 MB。`OriginalService.close()` 先关闭自动调度、清除定时器、终止自动工作线程，再等待在途任务结束并关闭手动任务。旧取消响应不能再次提交。该实现没有新增 Python 进程或 AI 模型调用。

## 数据兼容

未新增 SQL 表或数据库 schema 版本。`source`、`sourceState`、`sources`、`pendingSegments` 是现有对齐 JSON 的可选字段，旧数据可以直接读取。缺少来源依据的人工记录采用上述保守保留策略；自动记录只有在文字、片段 ID、原 ASR 时间和匹配版本满足复用条件时保留。
