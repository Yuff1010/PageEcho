# 自动字幕进度、取消与设置层级

`0.23.0-dev.2` 修正播放后只有静态提示、任务取消藏在文稿工具里，以及设置折叠组难以辨认的问题。

## 可见的实时状态

打开一集开始自动转写后，阅读页直接显示任务卡，不再把“生成本集字幕／查看字幕生成”当作正在工作的主要入口。检查组件、排队、解码、加载模型、识别语音及整理标点各有阶段文字；尚无可计算分段总数或正在加载时显示旋转图标和不定进度条，完成分段后显示真实的已完成／总段数。

进度条按真实完成分段计算，不按动画虚构百分比，也不把最远处理的音频位置当作完整覆盖率。已有字幕覆盖与本次生成进度分别保存和显示。新稿等待采用时仍明确保留当前正式文稿。

首段完成后正文正常显示，紧凑任务卡仍保留在正文上方；小说原文模式也能查看进行中的任务。底部播放器在任务运行时显示正在转写／加载／排队，而不是只显示“字幕未准备”。“收听工具 → 字幕与缓存”和文稿工具使用同一进度卡，接收相同状态通知。

## 取消与重新开始

任务卡直接提供“取消字幕生成”。检查组件、尚未创建任务时也能取消；已有任务在排队、模型加载及生成部分字幕后均可取消。停止进程需要确认时显示“正在取消…”并禁用重复点击，随后明确显示“字幕生成已取消”。已经完成的字幕和原收听位置保留，普通音频继续播放。

用户取消不会被继续播放、切集回来、下一集准备或离线队列偷偷重启。无任务的检查取消意图在本次运行内按音频版本保留，已有取消任务的状态持久保存。要恢复，明确点击“重新生成字幕”或任务重试；单纯恢复声音播放不视为重新生成。

普通播放的组件检查仍在等待时，即使“生成本集字幕”的主动请求已经排入，随后取消也会使该请求失效，不会在检查结束后重新启动。取消完成后，用户再次明确点击重新生成，才允许开始新的准备。

取消请求校验集数、音频哈希和当前播放会话；旧会话不能取消新会话。取消其他书籍的任务不会中断当前书的能力检查。切集不再把用户取消中的任务改写成自动恢复原因。关闭应用、切集的正常检查失效与用户主动取消仍按不同语义处理。

## 设置控件的区分

- 折叠组：有完整边框和标题区，左侧箭头随展开旋转，右侧写明“展开／收起”；整行可点，也支持 Enter／空格。
- 已展开内容：使用缩进、层级竖线与内容底色，嵌套参考区保持独立边框。
- 选择框：当前值位于独立方框中，右侧下拉箭头和分隔线与折叠组区别显示，键盘焦点有清楚描边。

深色、浅色及深色应用中的纸色阅读抽屉分别检查文字对比度和 720px 窗口布局。设置组继续使用原生 details/summary，选择框继续保留原生 select 语义。

## 验证入口

`transcription-progress-ui.spec.ts` 使用真实 Electron、IPC、SQLite、队列，以及受控 Python 能力检查／worker 协议，验证尚无任务、排队、模型加载、分段进度、停止确认、保留已生成内容、继续播放不重启及设置同步。该测试不运行真实识别模型，不新增准确率结论。

`settings-disclosure.spec.ts` 验证深浅主题、纸色抽屉、对比度、选择框与折叠组的区别、键盘操作及窄窗口。后端单元与队列测试覆盖用户取消原因、旧会话隔离、无任务取消、下一集／离线队列拦截及加载取消。验证日志与截图位于 `cache/subtitle-progress-validation/` 和 `cache/subtitle-progress-verified-tests/`。
