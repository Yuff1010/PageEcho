### P2：长文件名把记录行和移除按钮撑出窗口

- 复现：选择文件名为 `很长的中文音频名称 ` 重复 10 次、后缀为 `.wav` 的非空本地文件，将窗口缩至应用允许的 720×600。该用例只验证 M0 文件元数据，不验证音频解码。
- 预期：文件名省略显示，记录行保持在窗口内，移除按钮可见。
- 实际：页面可视宽度 704 px，文档宽度 1392 px；记录行右边界约 1392 px，移除按钮右边界约 1375 px，需要横向滚动才能操作。源码生产构建重复复现，打包 EXE 同样复现。
- 定位：`src/renderer/src/styles.css` 的 `.file-list` 使用 Grid，但列/子项没有限制最小宽度；长文件名的内在宽度撑开了网格项，仅对 `.file-info` 设置 `min-width: 0` 不足以限制整行。建议在网格列或直接网格子项上约束宽度，修复后运行该用例确认按钮仍可见。
- 复现命令：先运行 `npm run build`，再运行 `npm run test:desktop -- --grep "minimum window"`。
- 截图：`test-results/acceptance-packaged/m0-acceptance-minimum-wind-bc60c-ffline-with-a-long-filename/minimum-window.png`；同目录的 `trace.zip` 包含失败轨迹。测试报告附带 `layout` JSON，记录实际尺寸与溢出元素。

本轮没有观察到数据库记录丢失、错误删除原文件或主流程崩溃。以上结论限于实际测试范围。

受限执行沙箱内曾无法启动 Electron 图形进程；在正常 Windows 会话中通过。应用自己的 `sandbox: true` 与 `contextIsolation: true` 始终开启，测试未使用 `--no-sandbox`。
