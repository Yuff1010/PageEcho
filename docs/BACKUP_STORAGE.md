# 备份恢复与生成物保留

应用设置中的“备份与存储”提供两个互斥面板。备份前暂停播放，等待导入、字幕和离线任务结束；有活动任务时主进程拒绝开始备份或恢复。

## 书架备份

导出到一个新的 ZIP 文件，不覆盖已有备份。内容包括书架、播放／阅读位置、书签、人工文稿与映射、数据库内已有正文、应用／阅读偏好、已保存的原封面，以及经过脱敏的个人书库连接。SQLite 使用在线备份 API 生成独立快照，不直接复制仍在写入的数据库文件。

备份不打包外部音频与原书文件、模型、可重建缓存、书库密码／令牌、字幕组件绝对路径、插件执行包。插件只记录公开名称和版本；迁移到另一台机器后按需重新安装，个人书库凭据需要重新填写。原本地音频文件的路径仍作为书架记录保留，迁移后须在对应路径提供文件。现有机器恢复时保留本机安装的插件及其健康检查／更新地址记录，不从 ZIP 恢复脚本。

选择备份后先显示版本、书籍与书签／文稿数、体积和排除项。只有点击“恢复并重启”才准备替换。预览 15 分钟有效；准备完成后走正常退出保存流程，重启时在打开任何数据库和任务队列之前恢复。

每个文件校验路径、大小和 SHA-256，数据库执行完整性和版本检查。备份拒绝路径穿越、链接、未知数据文件、较新数据库版本与超过本版 256 MiB 的展开内容。准备目录在重启时再次校验；检查失败保持原书库。替换失败自动回退原目录；进程在两次目录重命名之间退出时，下次启动优先恢复保留的原目录。替换已完成而偏好尚未确认的情况，会完成偏好恢复，并在渲染器成功写入后确认，避免每次启动重置用户后续设置。

原数据完整保留在用户数据目录 `maintenance/rollback/<标识>/data`，不会由生成物策略删除。回退本身遇到磁盘或权限错误时停止启动并显示保留位置，需要先恢复该目录；不能把这种情况当作成功恢复。备份不是加密容器，含有书籍内容与个人阅读资料，应保存在用户信任的位置。

## 应用生成物

“存储”仅管理应用创建且带有生成回执的未来临时内容，目录为用户数据下 `cache/generated-artifacts/`。默认关闭自动清理，每类至少保留最新两份，默认配额 2 GiB、保留期 30 天。保留项或活动任务可以使占用超过配额，界面会显示这种情况，配额不是删除用户内容的授权。

手动清理先产生 5 分钟有效、单次使用的预览，再按预览确认。执行前重新核对策略、回执、目录身份、文件大小和修改时间；发生变化则停止。活动／未完成任务、链接、未知目录和无法核验的文件均保留。删除负载时最后移除回执，使磁盘错误后留下的生成物仍可重新核验。

模型、离线音频、备份 ZIP、恢复回退数据、外部书籍与根目录 `out/` 不属于此策略。旧工作区缓存和历史发行目录也不会自动登记或删除。

## 开发工作区

新的 `build:preview`、`pack:preview`、`pack:handoff` 将中间生成物放入 `cache/managed-generated/<UUID>/`，任务结束后写入完成回执；失败且进程正常结束的输出也可按策略处理，进程异常退出留下的未完成回执继续受保护。最终自包含程序与 ZIP 仍保留在 `release/`。

工作区策略独立于应用设置，由以下命令管理：

```powershell
npm.cmd run workspace:storage -- state
npm.cmd run workspace:storage -- preview
npm.cmd run workspace:storage -- policy --automatic false --keep 2 --max-gib 2 --days 30
npm.cmd run workspace:storage -- apply --token <预览返回的token>
```

Windows 下会检查运行中进程的命令行以保留正在使用的输出；无法读取进程信息时保留全部候选。预览与执行可以跨命令调用，过期、已消费或策略／文件变化的 token 被拒绝。只有明确开启 `--automatic true` 后，后续任务完成时才应用该策略。

历史批量清理与测试源码删除此前被自动审批拒绝，实际释放仍为 0 字节。本功能预防新的生成物无界累积，没有绕过历史拒绝，也没有将旧内容移入新的自动清理范围。历史清点见 [存储核对](STORAGE_CLEANUP.md)。
