# 应用内试听校对与引擎试用参考

日期：2026-10-23。本文记录高优先级第 6 项的可用工具与证据边界；真实小说人工验收仍未完成，第 6 项不因工具上线而完成。

## 在应用中填写

1. 打开一集的伴读，生成并应用整集字幕，或导入覆盖完整音频的文稿。生成中持续自动更新的稿件不能冻结听审；覆盖缺失也不能按已有部分跳过样本。
2. 点击伴读标题附近的“试听校对”，再选“建立本集固定试听样本”。首次按句子序号的 15%、50%、85% 取样，每句带前后各至多 1.5 秒上下文；短文稿重合位置合并，三个抽样点的来源均保留。单个上下文超过一分钟时明确拒绝建立，不能静默丢弃长句。
3. 试听音频，按显示的**目标范围**填写实际听到的文字，不包含上下文。机器文字默认隐藏，人工参考不从 ASR 或小说 TXT/EPUB 自动填入。听不清时选“未知”；明确目标无语音时选“确认目标范围没有语音”，与未填写参考区别记录。
4. 分别核对专名和同步。专名需明确确认已检查，包括确认没有专名。同步判断不自动生成；可选的人工声音起止使用原媒体秒数，未知端点留空，不用机器边界或零替代。
5. 点击“保存本片段校对”。关闭后及应用重启后可恢复；未保存修改不会写入数据库。关闭试听不会自动恢复主播放器。
6. 需增加样本时，关闭弹窗，在文稿中点击目标句，再打开弹窗选择“添加当前播放句为额外样本”。固定样本及已有追加样本不能删除，分母不会随追加或重新进入缩小；重复追加同句不会复制样本。

独立试听使用已注册的本地音频媒体协议，打开弹窗会暂停主播放器；切样本、关闭、切集、应用退出 flush、主播放器开始播放均暂停独立试听。后台进度通知仅复核冻结身份；正式文稿版本变化时暂停并转为只读，同一冻结稿的未保存输入保留。保存期间的通知合并到人工响应之后处理；关闭或切集后抑制迟到的读取结果。弹窗只汇总已听、有参考、未知、专名、同步判断和人工边界数量，不将完成填写称为质量通过。

## 保存与版本保护

用户数据目录的 `data/listening-reviews.sqlite3` 独立保存冻结来源和人工反馈，启用 WAL、foreign_keys、busy_timeout。冻结身份包括音频 SHA-256、文稿 ID/修订/种类、目标句 ID 与机器文字/时间、三个固定抽样点、创建时间；只有能对应当前已应用修订的生成任务才附带引擎、设备、任务与尝试次数，否则来源明确未知。未读取小说文字充当人工参考。

每次保存携带校对修订号，以 SQLite 原子 compare-and-swap 防止旧窗口覆盖新修改。读写再次校验当前音频注册身份及文件状态、冻结文稿版本；文件变化不能继续编辑。换稿后旧记录保留为只读，可在版本列表中查看，再为当前修订建立新样本。读取损坏或缺失固定抽样点的记录时拒绝计算质量状态。字符串、样本数、片段时长和记录大小均有上限。

此流程的三个固定点只是可扩展的本集首轮抽样。它**不缩小或替代** [LISTENING_REVIEW.md](LISTENING_REVIEW.md) 中《青山》9 段与《呐喊》3 段共 12 段的既有真实小说验收。那些固定包仍为 0/12 人工听审，人工文字、映射判断和发音端点没有由本功能补写。应用反馈和开发侧原文映射反馈也不是同一个 schema，不能把应用同步判断自动转换成原文映射正确标签。

## 现有引擎参考的独立审计

统一“字幕与伴读”设置中的“试用引擎参考”保留手动选择，不自动选择或保存引擎。下表来自现有 12 次完整真实 worker 配置（3 种材料 × 2 引擎 × 2 设备），复用了已运行结果，没有重新推理。

| 固定人工参考材料                 | 样本 / 参考字数 | Paraformer CPU / CUDA CER | WhisperX CPU / CUDA CER |
| -------------------------------- | --------------- | ------------------------- | ----------------------- |
| AISHELL-3 两位说话人干声短词短句 | 40 / 267        | 1.87% / 1.87%             | 43.45% / 43.82%         |
| AISHELL-4 同一场会议的连续片段   | 3 / 1012        | 8.30% / 8.40%             | 18.68% / 18.87%         |
| CH-SIMS 影视短片段               | 18 / 244        | 9.84% / 9.84%             | 15.98% / 16.80%         |

CER 以整组编辑距离除以整组人工参考字数，使用 NFKC、casefold、字母/数字保留规则，不转换数字写法、繁简或同音字。干声集合的数字写法差异对 WhisperX CER 影响很大，不能把 43% 直接理解成 43% 的语音内容听错。会议材料来自同一场会议，影视片段很短，训练材料重合未知。这些参考最多支持“Paraformer 可先试用”的暂定提示，不支持小说准确率、专名准确率、人工发音边界精度或默认引擎正式验收。

影视比较采用修复后双方均完成全部 18 段的结果；较早 WhisperX 仅完成 14/18、15/18 的失败运行不能用完成部分 CER 代替完整比较。三个数据集也不合并冒充额外独立书籍证据。

可复验命令：

```powershell
python -B -X utf8 scripts/audit-engine-reference.py
```

默认读取并比较 `src/shared/engine-reference.json`，独立新建 `cache/asr-evaluation/engine-reference-audits/<时间>/audit.json`，拒绝覆盖已有输出。快照逐项保留 summary/report/人工 manifest 的路径与 SHA-256、重建文稿及 checkpoint 清单摘要。审计还复核 PCM 摘要、完整固定集合、首次运行零缓存、重放与重启复用、checkpoint 归属/重建及独立重算 CER。不是只把 summary 数字复制到界面。
