# 0.38.0-dev.1 — 在线首段播放

交付日期：2026-11-02（America/New_York）。本版让首次在线 MP3 可以在首段落盘后开始收听，同时保留完整音频身份与字幕、进度语义。流程与回退说明见 [在线首播](../PROGRESSIVE_PLAYBACK.md)。

## 行为与结构

- 主进程 `OnlineMedia.preparePlayback` 在同一次 200 GET 正文写入至少 32 KiB、前缀确认后提供临时播放；不向 renderer 暴露媒体站地址或请求头，不用多响应拼接。未知长度、已有完整哈希、有上次未完成位置或“先准备字幕再播放”继续完整缓存路径。
- 新 `ProgressiveMedia` 只负责本机 spool GET／HEAD／单 Range：独立只读句柄、显式偏移、64 KiB 读块、最多 16 reader、缺数等待最多 120 秒。远处 seek 等待下载，非即时远端 Range；取消／失败／退出唤醒并收尾 reader，创建中连续取消不耗尽配额。
- 完整文件仍按原长度、格式、fsync、SHA、rename 和事务注册。pending 不创建 `StoredAudio`、不启动 ASR／映射／旧哈希书签；完成后只移交身份，保持同 audio、URL、时间和暂停／播放状态。手动字幕模式和原文人工保护不改变。
- schema 18 增加独立 `online_pending_progress`。Main 的 session lease、已落盘前缀 SHA 和总长约束暂存进度；重启先完整取得并核对前缀，失配从零开始。保存使用已有缓冲数据确认的位置，未缓冲的远处 seek 目标不落成已听位置。完成事务只改该集，不覆盖后来选择的全局当前集／倍速／音量。
- `database-schema.ts` 共用数据库打开及备份恢复上限，17 可迁移至 18；完整备份自然包含暂存快照，活动 lease 和 `.part` 不进入备份。升级后请勿让仅支持 schema 17 的旧程序打开该库。
- 缓存百分比使用现有字幕图标和 Tooltip；尚无哈希的阅读等待页复用 `ReaderToolbar`／标题 h2／`ReaderDock`，完整提交前后几何一致。没有增加平行状态栏或大进度卡。
