# 缓存、任务与日志

0.6.0，2026-10-20。入口为顶部“缓存与任务”，schema 仍为 v5。普通播放不需要配置模型或启动 Python。

## 用户操作

- 存储与组件：查看分块大小、组件资源目录统计、Python/FFmpeg/模型清单位置和模型路径。可从原生选择器更新组件配置；有运行或取消中的任务时先等待或取消，恢复排队但组件缺失时仍可选择配置。
- 清理：先完成或取消所有排队、运行、取消中任务，再“预览清理分块缓存 → 确认清理分块缓存”。原音频、模型、已保存文稿、书签、进度和任务历史保留；再次生成可能重算已清理块。
- 转写任务：每页 25 项，显示状态、处理次数、完成/复用块和错误，可过滤活动项、取消或重试。旧音频版本的任务不能重试。
- 应用日志：以普通文本显示本机 `logs/app.log` 最后 64 KiB，可打开日志目录。日志可能包含本地音频路径和模型诊断，不自动上传。

## 清理边界

候选仅来自当前组件 `cache/jobs/<64 位小写十六进制>/`。manifest 须为 worker 的 v1 结构，原范围有效，配置、音频 SHA-256 与原范围计算的指纹须等于目录名；Python 和 Node 的指纹有独立固定值及真实 worker 验证。

目录只允许 `manifest.json`、`chunk-000000.json` 等分块及带 UUID 的原子写入 `.tmp` 文件。任何未知文件、嵌套目录、符号链接、junction 或不匹配清单都会保留整组。仅有临时文件而缺少有效 manifest 的目录也保留，不能推断为可清理数据。

预览只返回随机 token 和大小/数量，不接收 renderer 路径。token 五分钟有效、仅使用一次；再次检查组件路径、清单、目录身份和文件属性，变化则拒绝。删除前重新检查真实目录与包含关系，逐文件 unlink，最后只对空目录 rmdir。没有对资源根、模型或任意目录执行递归删除。

清理要求当前应用没有 queued/running/canceling 任务，关闭空闲 worker 后独占执行。期间禁止生成、重试和更换组件；应用退出等待清理结束。活动队列、文件选择和清理冲突返回可操作的 BUSY 信息。外部进程也可能改变文件，清理失败时保留剩余内容并刷新查看，不承诺跨进程文件系统事务。

## 大小与诊断限制

显示的是文件长度合计，不等于磁盘实际分配块。资源统计不展开链接，限制深度 24、100,000 项及约五秒的分步统计预算；未遍历完或部分不可读时明确标注。清理候选扫描最多 10,000 组、每组 20,000 文件，并按组检查总量/耗时预算；过大或读取慢时要求稍后重试，不静默扩大删除范围。

模型“路径存在”仅说明位置可访问，不证明模型版本、依赖或 GPU 已通过推理检查。模型清单在文件管理器中定位，打开目录只接受固定目标枚举，不接收文件路径或执行命令。0.7.0 已提供[独立离线包](ASR_COMPONENT_BUNDLE.md)，v2 将只读资源与用户目录中的可写缓存分开；应用内下载/更新器尚未实现。

## 验证

普通检查不下载模型：`npm run verify -- --asr`。新增检查覆盖未知文件保留、指纹伪造、junction 和预览后的目录替换、内容/配置变化、维护与排队/生成/重试/退出的互斥、分页和有界日志。源码桌面测试执行真实 IPC、SQLite、清理和文稿保护，仅替换原生选择器返回值。

`npm run asr:app` 使用独立用户目录和新的 checkpoint 目录，真实运行整首歌曲。0.6.0 报告 `cache/asr-evaluation/app-runs/2026-10-20T05-03-29.592Z/report.json` passed：活动任务拒绝清理，界面清理后原文稿不变，再次生成命中 0 块并保持当前文稿。原媒体、模型和日常缓存未被清理。
