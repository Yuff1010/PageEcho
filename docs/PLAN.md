# 开发计划

更新日期：2026-10-18（America/New_York）

## 1. 目标与当前状态

做一款自己日常使用的 Windows 听书软件，以“保留现有演播音频，同时看到同步文字”为核心。

当前已完成需求讨论和框架选择；本次交付为仓库与规划文档，不代表应用功能已实现。下列里程碑均按验收结果推进，不预先承诺未经估算的日历排期。

用户已确定 Windows 优先、Electron + React + TypeScript。其余组件按本文给出的默认方案验证；模型、首个在线书源和性能门槛仍待样本实测。

## 2. 范围

### 第一个可日常使用的版本（M0–M4）

- 本地文件/文件夹导入、书架、章节目录及最近播放。
- 播放、暂停、倍速、快进快退、自动下一集、断点续播。
- 句级转写稿、高亮、自动滚动、点击跳转、手动浏览后返回当前句。
- 转写任务状态、取消、重试、已有片段复用和缓存管理。
- 基本文稿纠错、简单定时停止、书签、单书片头片尾设置。
- Windows x64 打包验证；其他架构按实际设备需求后续扩展。

### 本地版本稳定后（M5）

- 选定一个在线书源，接入搜索、详情、目录和音频地址解析。
- 登录会话、必要请求头、音频缓存、网络错误及地址过期恢复。
- 当前集优先和下一集转写预处理。

### 后续增强（M6）

- TXT/EPUB 原文导入、音文跨集跨章匹配、人工校正与原文/转写稿切换。
- 文稿搜索和字幕导出。
- 云同步、网盘、广播、移动端及公开插件市场不纳入当前交付范围。

| M2 | 使用人工时间戳的伴读原型 | M1 | 高亮、滚动、点句跳转与媒体时间一致 |

### M0：工程基础

- [ ] 使用 electron-vite 建立 React + TypeScript 工程；确认 Electron、Node.js、构建工具与 SQLite 驱动的兼容组合，提交锁文件。
- [ ] 划分 main、preload、renderer、shared；主进程与渲染进程使用明确的 IPC 契约。
- [ ] 设置 contextIsolation、sandbox，关闭 renderer 的 Node 集成；preload 只暴露必要方法，并校验请求参数。
- [ ] 建立用户数据、缓存、模型、日志目录；不写入安装目录，不把绝对路径写死。
- [ ] 选择 SQLite 驱动，验证数据库迁移及 Electron 打包后的原生依赖加载（如有）。
- [ ] 加入 TypeScript 检查、格式化、lint 和有意义的基础测试入口。
- [ ] 制作最小 Windows x64 安装包，在没有开发环境的目标环境验证启动。

验收：可显示最小窗口，经 IPC 选择本地文件并返回受控结果；安装版能创建数据目录、读写数据库并正常退出。README 增加实际验证过的开发与构建命令。

### M1：本地听书

- [ ] 导入单个文件或文件夹，确认章节顺序，记录文件路径、大小、修改信息与内容哈希。
- [ ] 建立长期存活的播放器控制器，使用 HTMLAudioElement，页面切换不重新创建播放器。
- [ ] 通过受控媒体协议或本地媒体服务读取文件；验证范围读取和跳转，避免把长音频整段加载进 JS 内存。
- [ ] 实现播放、暂停、音量、倍速、快进快退、拖动及播放结束事件。
- [ ] 保存书籍、当前集与媒体时间；节流保存并在暂停、切书、退出时补存。
- [ ] 自动下一集；文件缺失、损坏或不支持时显示可操作的错误。
- [ ] 测试关闭到托盘、恢复窗口和显式退出的生命周期。

验收：MP3 与实际来源的 M4A/M4B 样本可完成播放、倍速和跳转；重启恢复同一集和位置。M4B 内嵌章节先验证读取可行性，无法支持时明确按单个音频文件处理。记录格式限制，不以扩展名推断全部编码均可播放。

### M2：独立验证伴读

- [ ] 定义带音频版本标识的句级 JSON 文稿，字段包含片段 ID、startMs、endMs、text。
- [ ] 使用人工标注的短文稿先验证同步，不依赖识别模型。
- [ ] 根据播放器媒体时间查找当前句，定义句间静音、未转写区间和音频结束时的显示状态。
- [ ] 当前句高亮、自动滚动、点击句子跳转、拖动播放后的重新定位。
- [ ] 用户手动滚动后暂停自动滚动，提供“回到当前播放位置”。
- [ ] 大量句子采用分页或虚拟列表，避免整集文稿每次进度更新都重新渲染。
- [ ] 显示文稿类型、加载状态和缺失区间，支持字号、行距、主题。

验收：0.75x、1x、1.5x、2x 下暂停/恢复和来回跳转不累计漂移；原文第 19 章位于音频第 32 集中间的例子不依赖章号对应。点击一句后播放位置与对应媒体片段一致，手动阅读不会被反复拉回。

### M3：转写模型与任务系统

- [ ] 建立代表性中文样本集：单人干声、背景音乐、多人对话、专有名词、片头广告、较长单集。
- [ ] 在实际 CPU/GPU 设备上比较 FunASR、WhisperX 等候选，分别测量识别和对齐质量。
- [ ] 记录模型与版本、配置、音频时长、处理耗时、首段等待、峰值内存/显存、人工标注的时间偏差和专名错误。
- [ ] 根据评估选择第一版默认引擎，并将理由写入技术决策记录；保留可替换适配接口。
- [ ] 使用 Python 独立进程实现 submit、progress、result、cancel、error 协议；FFmpeg 按选定流程负责解码和切段。
- [ ] 音频切段保留原时间偏移，处理重叠区的重复和漏字；广告标记不改变原时间轴。
- [ ] 持久化排队、运行、完成、失败、取消状态；重启恢复、可取消、可重试，忽略过期任务结果。
- [ ] 缓存按音频内容版本、引擎/模型版本、处理参数与文稿版本区分；支持复用已完成片段。
- [ ] 支持逐步显示已完成片段；未生成或失败时保留普通播放。
- [ ] 支持小范围文字纠错并保留时间戳；句子拆分合并和大幅改写进入重新对齐流程。

验收：至少三类中文样本可完成“生成文稿→边听边看→重启复用”；切书可取消任务，失败可重试且不损坏已完成片段。性能报告明确是否能在目标设备边听边处理，不预先承诺实时转写。

### M4：日常使用与发布候选

- [ ] 完善最近播放、书签、简单定时停止和单书片头片尾设置。
- [ ] 片头片尾跳过使用原媒体坐标，自动下一集不会重复触发或遗漏进度保存。
- [ ] 提供缓存占用、清理、模型位置、任务状态和错误日志入口。
- [ ] 确定模型与 Python 运行时的分发方式；让目标用户按需安装所需组件，普通播放可独立使用。
- [ ] 验证带空格/中文路径、只读安装目录、断网、磁盘空间不足、音频被移动和任务进程退出。
- [ ] 验证安装、升级保留数据、卸载行为说明及启动恢复。
- [ ] 发布第一个自用版本，并更新 README、已知限制和人工验收记录。

验收：没有 Node.js/Python 开发环境的 Windows 设备可按说明安装和使用；连续收听、托盘恢复、重启与数据库升级不丢进度。具体内存和时间戳误差目标由 M1/M3 基线确定后写入发布检查表。

### M5：在线书源

- [ ] 选定一个实际使用的网站及音频样本。
- [ ] 定义 SourceAdapter：search、getBook、getEpisodes、resolveAudio；可选 discover、authenticate。
- [ ] 在主程序外部任务层执行网络访问，支持超时、取消和单源错误隔离。
- [ ] 登录网页使用隔离会话，不向第三方网页开放应用 IPC 或任意文件权限。
- [ ] 音频获取层处理必要请求头、Cookie、Range、重定向、URL 过期和缓存版本。
- [ ] 完成按源展示结果、章节加载、播放和文稿复用。
- [ ] 加入当前播放附近优先、下一集预处理和清理策略。

验收：第一个来源可完成搜索、选书、目录、播放、续播与伴读；网络/登录失败可解释并可恢复。接入第二个来源后再评估插件协议，暂不承诺兼容随身听书现有插件。

### M6：小说原文对齐

- [ ] 导入 TXT/EPUB，建立版本化的章节、段落、句子索引。
- [ ] 转写文本检索原文并生成候选映射，避免按集号/章号固定绑定。
- [ ] 支持一集跨多章、一章跨多集、演播插话与删改。
- [ ] 记录匹配置信信息和人工校正，不确定部分保留空缺。
- [ ] 支持原文/转写稿切换，同步点编辑和重新对齐。

验收：至少覆盖“第 32 集从第 19 章中间开始”、跨章、删改和插话样本；缺失内容不被强行映射成原文。

## 4. 验证方式

| 层级 | 优先测试内容 | 方法 |
| --- | --- | --- |
| 纯逻辑 | 时间区间查找、章节自然排序、缓存版本、任务状态转换、分段偏移 | 单元测试；使用人工确定的期望值 |
| 模块集成 | IPC 参数校验、数据库迁移、进度持久化、转写进程退出/取消/重试、Range | 小型可重复夹具和集成测试 |
| 桌面操作 | 导入、播放、点击句子、切页、托盘、重启 | 自动化关键流程 + Windows 人工验收 |
| 模型质量 | 中文识别、专有名词、音乐干扰、时间偏差、资源占用 | 固定样本与人工标注；独立评估，不在普通 CI 下载模型 |
| 分发 | 无开发环境启动、数据库读写、模型组件就绪、升级保留数据 | Windows 安装包验证 |

不为纯文档或样式改动添加重复测试。每个阶段完成后记录实际结果；没有跑过的检查明确标记“未验证”。
