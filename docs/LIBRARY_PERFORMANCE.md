# 大书架读取优化

0.42.0-dev.1 首先优化 Main 读取和后台单书操作，保持完整 `Book[]` 的旧接口，不把部分章节伪装成完整书籍。摘要／详情 IPC、有限书卡渲染和独立播放上下文仍待下一阶段。

## 已实现

`LibraryStore.listBooks()` 从每书三次读取改为三次数据读取：书籍元信息、全部本地章节、全部在线章节。章节逐行迭代映射，按原书序分组并稳定排序；复用原一致性读快照，因此还有两次快照控制，总 SQL 数固定为 5，与书数无关。AppState 的历史／偏好另有两次读取，两种实现都相同。

复用同一投影提供内部 `getBookMetadata`、完整单书 `getBook`、`getBookEpisodeAtOrder`、`countBookEpisodes`、`hasBookEpisodeAfter` 和 `listBookIds`。自动字幕、下一集准备、在线目录续载、离线计划、关联目标和移除操作按目标读取，不为操作一本书先装入全库。启动恢复仍使用原书架顺序和 10,000 个目标上限。

本地从 0 开始的序号、在线从 1 开始的序号和同序号原分支优先级保留。精确 `order + 1`、存在任意更大序号、离线范围按已排序数组位置是三个不同操作，不能互换。在线暂存位置不覆盖已注册音频的零位置或 null 时长；缓存身份、人工文稿及原文映射保持原样。复合读取在同一 WAL 视图，已有调用者事务不会被内部提交。

## 同输入测量

真实 schema 18 的独立合成数据库，各实现、各规模三轮新 Node 进程中的首次读取，系统磁盘缓存未清空。建库事务分别约 4.48 秒和 449 ms，单独记录，不混入读取耗时。选择的当前书位于返回结果末尾。未下载音频、书籍或模型，未测实际 IPC、界面首帧或干净设备。

| 合成数据         | 旧读取中位数 | 新读取中位数 |   降幅 |  读取 SQL |        完整 JSON |
| ---------------- | -----------: | -----------: | -----: | --------: | ---------------: |
| 5000 本 × 200 集 |   3674.90 ms |   2341.95 ms | 36.27% | 15001 → 5 | 304,733,765 字节 |
| 1 本 × 100000 集 |    416.48 ms |    253.76 ms | 39.07% |     4 → 5 |  30,592,910 字节 |

六轮候选全部完成，无 OOM、超时或跳过；完整 AppState 形状 JSON 的字节数和 SHA 与独立旧 SQL 投影逐轮相同。百万集 JSON SHA-256 为 `b26c8bbc56edd03e22aa5d6bb1934f32f009cd4e8f161014a93bcfe17247181d`。旧数据库字节摘要保持不变，没有覆盖旧报告。

百万集读取后 heap 中位数从 391.51 增至 412.19 MiB，RSS 从 590.47 降至 583.79 MiB；不能称全面降低内存。额外 JSON 序列化／UTF-8 计数后的进程峰值从 1708.14 变为 1701.00 MiB，这不是纯读取或实际 IPC 峰值。JSON 序列化中位数从 562.73 增至 583.11 ms，未改善。单书十万集读取后 heap 为 159.28 → 62.73 MiB，RSS 为 308.76 → 152.78 MiB。

实际 `EXPLAIN QUERY PLAN` 显示单集 ID 读取使用主键，单书／计数／序号读取使用 book_id 索引。旧 UNION 本来就能下推 book_id 条件，不能说它每次都全表扫描。本地序号仍按所选书范围过滤，部分排序仍需临时结构；本版不新增 schema 或索引。
