# 技术决策记录

更新日期：2026-10-20（America/New_York）

## 已确定

### D001：Windows 优先

用户目前只需要 Windows。首先验证 Windows x64；其他平台与架构不作为第一版验收条件。业务与数据模块保持可拆分，但不为尚未确定的平台投入实现工作。

### D002：Electron + React + TypeScript

用于桌面主程序和界面。React 负责书架、目录和伴读交互，Electron 提供文件、窗口、托盘与任务进程管理，TypeScript 描述 UI 状态和 IPC 契约。

接受 Electron 自带 Chromium 与 Node.js 的运行时开销。安装体积、启动与内存表现通过原型记录，不使用未经本项目测试的性能数字。此次选择不依赖复用第三方项目代码。

## 分阶段采用的方案

### D003：先本地播放与转写伴读，再在线书源

先用人工文稿验证时间同步，再接入识别模型，便于区分播放器、时间轴与模型识别的问题。后续通过共享媒体和转写服务服务所有书源。

### D004：HTMLAudioElement 作为初始播放器

使用媒体时间、倍速、跳转和结束事件实现听书基础功能。需验证实际文件编码、长音频 seek、倍速音质、后台播放以及受控本地协议。播放器接口保持可替换；不预设所有格式都兼容。

### D005：Python 独立转写进程

便于使用开发者已有 Python 基础以及语音识别工具。通过结构化消息与 Electron 通信，避免阻塞 UI。代价是增加运行时分发、模型管理和进程恢复工作。

FunASR 与 WhisperX 均为候选，不预先认定中文识别或对齐胜出。也可在同一评估接口下增加其他引擎。云转写不作为第一版必需项。

### D006：SQLite + 文件缓存

SQLite 存储结构化元数据；媒体与模型存于文件系统。M0 采用 Electron 44.9.0 自带的 `node:sqlite`，实际内嵌 Node.js 24.22.0。开发与安装版均验证了 schema v1 迁移、写入、重启恢复及关闭；无须分发或重编译第三方原生驱动。

M1 的 schema v2 已加入书架、逐集进度与播放设置，保留原选择记录；文稿与任务表后续迁移加入。`DatabaseSync` 为同步接口，只用于小型元数据操作；音频扫描与哈希使用异步文件流，识别等耗时工作进入独立任务层。运行时升级时重复安装版数据库测试；不假设 API 永久不变。

### D007：electron-vite 与 electron-builder

已采用 electron-vite 6.0.0、Vite 8.3.4 与 electron-builder 26.15.3。Windows x64 NSIS 采用当前用户安装、允许选择安装目录、卸载保留用户数据；已完成本机安装/运行/卸载验证，干净设备验收待完成。

开发 Node 固定为 24.x（本机 24.19.0），React 19.3.1，TypeScript 6.0.3。选用 TypeScript 6 而非当时的 7，是因为 typescript-eslint 8.71.2 的 peer 范围为 `<6.1.0`。完整依赖由 npm 锁文件固定。

当前没有组件库或全局状态库，M0 用 React hooks 和本地 CSS。生产资源全部本地加载。代码签名与专用应用图标留待发布候选阶段。

### D008：先实现书源适配接口

首个在线来源采用内置适配模块；验证多个来源的共同能力后再确定可安装插件格式。没有决定兼容已有 DLL 或 JavaScript 插件，不将第三方插件文档当成已验证协议。

### D009：M1 本地媒体与进度边界

本地音频不复制，导入时流式计算 SHA-256，SQLite schema v2 保存书籍、章节、音频版本与逐集进度。受控 `readlisten://app/media/<ID>/<hash>` 协议只映射已入库资源，支持流式 Range；不经 IPC 传输整段音频或任意路径。

HTMLAudioElement 已通过两小时 PCM WAV、MP3 与 AAC LC M4A/M4B 合成夹具的播放、倍速与跳转验证；后续补充《呐喊》原始 MP3/M4B 及两份原始 AAC LC M4A 的解码、远距离定位、重启和约 10 分 24 秒跨格式自然连播，见 [有声书验收](AUDIOBOOK_VALIDATION.md)及 [M4A 验收](M4A_VALIDATION.md)。含内嵌章节的 M4B 当前仍作为单集，UI 明示限制；整书连续收听与其他编码仍待验证。普通播放无需 FFmpeg；可选转写组件使用 FFmpeg 有界解码。

窗口关闭进入托盘，显式退出通过 renderer 保存确认后关闭 SQLite；异常退出依赖每 5 秒及操作事件的最近成功写入。单例播放器跨书架/目录存活。M0 历史选择记录保留，并可通过 ID 重新检查、哈希后加入书架。

### D010：M2 先以有界文稿验证同步

句级 JSON v1 使用音频 SHA-256 和明确覆盖区间，不按小说章号匹配集号。SQLite schema v3 将每个音频版本的文稿作为 JSON 保存，重新导入增加修订号；输入限制为 16 MiB/100,000 句。文稿加载一次，二分查找媒体时间并每页显示 60 句。M3 的逐段写入与任务索引再扩展数据结构。

阅读时通过 requestAnimationFrame 读取实际 currentTime，只在句子或空缺状态变化时更新文本。播放器进度条与保存仍使用原有节流；手动阅读暂停自动滚动，恢复跟随或窗口/字号变化时重新定位。纸色/深色、字号和行距保存在本地阅读偏好中。

### D011：统一验证与计划状态分开记录

`npm run verify` 顺序运行现有检查、开发窗口和生产桌面测试，可选 `--packaged` 扩展到安装包与打包程序。写入阶段日志和可机读报告，失败后停止依赖步骤。明确的系统策略拦截记为 blocked 并返回非零；测试不自动勾选真实样本或人工安装验收。

### D012：M3 模型评估与产品默认引擎分开

首批 3 个歌曲片段和 M2 中文 TTS 对照已在本机 CPU/GPU 运行 Paraformer 与 WhisperX。独立 Python 环境、完整依赖和模型 revision 固定，原始结果与媒体只在 Git 忽略的 cache 中；评估工具不进入普通 CI 的模型下载路径。详见 [M3 首轮评估](M3_EVALUATION.md)。

WhisperX large-v3-turbo 的 int8_float16/batch 1 GPU 配置作为任务接入的优先候选，CPU int8 路径也已实测。三首结果通过 M2 格式/原偏移检查和源码播放器重启复用；尚无人工歌词参考，且中文缺少标点、时间精度未验收，因此不将它设为产品默认引擎。Paraformer 对照 CER 为零，但实际歌曲出现 VAD 空结果和约 30 ms 的末尾越界，保留适配候选并继续研究。

质量报告区分文字识别、对齐、区间有效性和用户流程。模型返回时间戳不等于对齐准确；错误区间拒绝导出，不能用截断掩盖问题。歌曲和合成语音不替代多人、专名、片头广告、长篇听书与人工发音边界验收。任务实现应保留引擎替换和显式 CPU/GPU 配置，普通播放无需模型依赖。

### D013：M3 使用本地 JSONL worker 与原子分块缓存

Python 处理原媒体范围内的 30 秒核心块和 2 秒上下文；使用字/词时间中点归属、同时间重复去重及冲突保留/标记。WhisperX 识别后由 CPU ct-punc 插入标点，沿用原生时间，不通过固定秒数截掉文字或对异常时间静默裁剪。

Node 控制器一次接收一个 attempt，过滤旧任务/取消后的结果，用 M2 校验器再次验证文稿。取消请求可立即接受，原生推理在安全检查点停止；超时由 Node 停止其拥有的进程树。标准协议测试不依赖模型，实际模型验收使用单独命令。

分块文件按音频、处理范围、模型/依赖、计算配置、解码/断句资源及后处理版本区分，原子写入并在复用前校验；保留原始输出与冲突，完全命中可不加载模型。Python 不写 SQLite；应用队列和文稿修订保护由主进程调度层负责。协议、验证和已知限制见 [转写组件](ASR_WORKER.md)。

### D014：M3 持久任务与已有文稿分开保护

0.4.0 使用 schema v4 持久化任务状态、attempt、运行配置摘要及完整前缀快照，由主进程串行调度 Python。重启续接 running 任务时增加 attempt；正常退出先持久化续接状态并关闭拥有的进程，再关闭 SQLite。配置或音频版本不一致时不接纳旧结果，失败/取消保留完成片段。

首份文稿可逐块自动显示；已有文稿或人工修改时，生成稿仅供预览，明确采用且预期修订仍匹配才替换。导入、纠错及采用均在事务中更新修订并保护人工结果。小范围编辑保留时间戳；大幅改写、拆分合并及重新对齐不纳入当前实现。

可选组件配置只接受 Python、模型清单、资源目录、FFmpeg 和 ffprobe 路径，由原生选择器选取；worker 脚本固定为应用自带资源。普通播放无需这些组件，任务期间不下载模型。引擎仍由用户显式选择；歌曲流程通过不等于已选定默认引擎或完成听书质量验收。实际验证见 [M3 应用验收](M3_APP_VALIDATION.md)。

### D015：M4 书签与跳过保留原媒体坐标

0.5.0 的 schema v5 为书签和单书收听设置增加独立表，不改写原音频或文稿。书签使用 episodeId + audioHash + positionMs 定位，重复添加同一位置幂等；内容变化保留旧备注但禁止跳转。每书上限 2,000 条，每页 20 条。片头只影响打开章节时的默认起点，显式书签与点句跳转使用原坐标；过短单集完整播放。

片尾检测与原生结束使用同一完成标记，先确认进度保存再切集；保存失败、手动操作或过期加载都不能继续旧的自动切集。分钟定时采用绝对截止时间，暂停与托盘隐藏时计时；到期取消待加载音频的自动播放，本集结束定时优先于下一集。定时仅本次运行有效，重启后保持暂停并清除定时。验证见 [M4 记录](M4_VALIDATION.md)。

### D016：M4 只清理可确认归属的分块缓存

0.6.0 的管理入口显示组件和模型位置、文件大小、任务历史及本机日志。清理限定于已选资源目录下、manifest 与目录指纹一致的 worker 分块；未知项目和链接保留，不自动移除模型。用户先查看预览，再以一次性 token 确认；预览后变化则拒绝。逐文件删除并对空目录使用非递归 rmdir，不对资源根目录使用递归删除。

维护操作与活动转写互斥，先关闭空闲 worker，期间禁止生成/重试与更换组件；正常退出等待维护完成。任务和文稿留在 SQLite，清理后重新生成可重算而不覆盖已有文稿。真实歌曲已验证清理后缓存命中为零及原稿保留，详见 [缓存管理](CACHE_MANAGEMENT.md) 和 [M4 验收](M4_VALIDATION.md)。

### D017：M4 使用嵌入式 Python 的独立离线组件

0.7.0 从已验证依赖构建可选 ZIP：官方 Python 3.12.10 嵌入式发行版、140 项固定依赖、五个模型、FFmpeg 和断句资源。私有 `_pth` 加随包依赖，避免复制依赖机器安装位置的虚拟环境 launcher；不要求最终用户安装 pip 或开发工具。模型清单为相对路径，v2 资源与用户目录可写缓存分开。原 v1 配置保留。

包已跨盘迁移到中文/空格目录，隔离 Python 搜索路径下 CPU 对照、GPU 整首歌曲、重启、取消与缓存清理流程通过；这些证据不替代干净设备和主程序签名/安装验收。普通播放不等待组件初始化，迟到初始化不能覆盖新选择。Paraformer 的 worker 配置按实际 float32 记录，不将未使用的 WhisperX 量化参数误记成 Paraformer 精度。发行数据和验证见 [组件包](ASR_COMPONENT_BUNDLE.md)。

### D018：人工片段类型独立绑定原时间范围

0.8.0 将广告、片头和前情回顾标注保存在 schema v6 独立表，以音频版本与原媒体范围绑定，避免重新生成、分句或纠错破坏人工判断。沿用 JSON v1，不将人工标注混入模型缓存；独立修订和事务保护并发更新。

折叠只作用于完整包含的句子，部分重叠保持展开，音频播放不自动跳转。管理范围时替换原范围，逐句改类型时仅替换指定范围并保留外侧；没有文字的范围也有管理入口。自动广告识别与时间质量仍须真实样本评估，见 [片段标注](TRANSCRIPT_REGIONS.md)。

## Paraformer 的原生时间与 CTC 重新对齐（0.8.1）

固定 FunASR 1.4.16 wheel 的 Paraformer 时间戳调用颠倒 alpha/peak 参数，应用按已确认的版本/源文件哈希，对当前模型实例应用上游修正。修正后仍存在负起点/末端越界时，使用已分发的中文 CTC 模型对同一识别文字重新对齐，禁用插值；原生有效结果直接使用。缺失或非法字符时间仍失败，原生输出和重新对齐结果保留在缓存，并向任务记录 `NATIVE_REALIGNED`。

这样可保留识别文字和实际媒体坐标，不把模型帧长当作音频时长，也不用放宽通用文稿校验。代价是部分 Paraformer 块额外加载/运行对齐模型；缓存配置纳入适配契约、对齐模型和断句资源版本。独立组件文件保持原样，默认引擎仍由完整样本质量决定，见 [修复与实测](PARAFORMER_TIMESTAMPS.md)。

## 引擎已有标点只处理一次（0.8.2）

实际 43 分钟章节显示 Paraformer 的 CTPunc 输出被通用任务层再次补标点，造成重复句读。适配器明确返回 `punctuationRestored`：Paraformer 保留 AutoModel 已有标点，原生时间有效时仅附回既有锚点；CTC 路径保留同一识别表面文字。WhisperX 已输出句读的窗口保持原结果，其余窗口才调用通用标点模型。

任务层遵守该标记，缓存指纹加入 `punctuationPolicy: engine-surface-once-v1`，避免复用旧处理结果。原始输出、原媒体坐标、纠错保护与预览采用保留；不按出版原文强改模型词语。长篇每块的标点保留检查与人工识别质量分别记录，见 [验收](AUDIOBOOK_VALIDATION.md)。

## CTC 搜索计入完整波形（0.8.3）

实际 M4B 的 113 字长句被压到不足 4 秒；受控比较确认原 CTC 结束位置只最大化前缀累计分数，未计入尾部 blank 代价。应用在固定 WhisperX 3.8.6 源文件摘要匹配时，只复制调用方 align 函数的 globals，以逐帧 blank 对数概率为搜索基线。完整波形目标在原搜索图中等价于前缀分数减累计 blank 分数，回溯每一步的前驱相对顺序保留；逐帧实现避免长序列累计抵消。

原模块/模型/组件文件、识别文字、原概率与媒体时间不改写。WhisperX 和 Paraformer 的按需 CTC 共享该修正，缓存加入 `ctc-complete-waveform-logodds-v1`。人工边界质量、词表缺失及识别错误仍需单独评估，见 [CTC 证据](CTC_ALIGNMENT.md)。

## 用完整重叠上下文确定字符归属（0.8.4）

两边独立按时间中点裁切会同时排除同一字；仅按相同字和交叉时间去重又可能删除真实叠字。后处理版本 3 在 checkpoint 保存完整原生上下文，加载时验证范围及归属一致性。以同时覆盖双方切口、唯一且时间相容的共同文字位置判定归属；仅复制完整原生 unit，不制造字符时间。

无法确定的上下文保留选择结果并标记待复核，时间交叉保留并在阅读段按原范围合并。固定旧输出对照恢复四处归属丢字并保留“愤愤”，两个真正的重复归属仍去重；完整听审与默认引擎仍待验收，见 [窗口拼接证据](ASR_OVERLAP.md)。

## 连续参考先固定标注再运行模型

0.8.4 的评估补充按固定 AISHELL-4 标注选择三段不相交的连续范围，先保存清单和摘要再识别。保留完整口语和源偏移，不拼接短句或加入静音；用同一批实际识别窗口回放旧拼接，单独量化后处理差异。25 话轮/1012 字中，Paraformer CPU/GPU CER 为 8.30%/8.40%，WhisperX 为 18.68%/18.87%，各较旧规则少一个编辑错误。

该结果来自已经使用过的一场远场会议，训练重合未知。跨切口分数针对完整人工话轮，不推断逐字发音时间；不得直接外推有声书质量、替代听审或设置默认引擎。选择、参考篡改检查、CPU/GPU 结果及原书待听审摘录见 [连续参考证据](CONTINUOUS_REFERENCE.md)。

## 全文搜索与字幕导出（0.10.0-dev.2）

0.10.0-dev.2 的全文搜索采用按版本执行的有界 worker 扫描，归一化文字但不跨自然段/章节，每页 20 个句范围；没有新增可漂移的索引数据库。字幕导出绑定当前文稿和人工映射修订，仅输出已有原时间范围，未匹配处留空；保存框前后重新核对并使用临时文件替换目标。原文相邻片段可能重复整句，不据此生成逐字时间。见 [搜索与导出](READING_TOOLS.md)。

## 原文精确位置覆盖全书（0.10.0-dev.3）

原文规则 3 将“是否唯一”的检查从候选截断列表移到完整归一化原文。三元组检索仍负责有界近似候选；精确位置可补回被截断的唯一片段，并阻止未召回的重复原文被误当作唯一匹配。最多保存两个句范围和 256 条查询缓存，短句上下文必须全文只出现一次。实际复验和仍待人工听审的范围见 [真实跨集与歧义检查](ORIGINAL_SEQUENCE.md)。

## 繁简兼容只作用于检索（0.10.0-dev.4）

官方繁体 EPUB 与简体 ASR 的同作品检查暴露了单纯 NFKC 规范化的缺口。匹配规则 4 固定使用 `opencc-js@1.4.2` 的通用 `t → cn` 离线转换，匹配和全文搜索共用 main/worker 规范化函数；不向 renderer 增加字典，不改原文、保存的识别文字或原文字幕。繁简转换造成的重复仍经过全书唯一性校验。EPUB 图片封面修正单独升级解析版本 3，TXT 保持版本 2。许可证随目录包静态核对，真实输入及准确率边界见 [EPUB 验收](ORIGINAL_EPUB.md)和 [预览包验收](PACKAGE_PREVIEW.md)。

## 当前集转写稿搜索（0.10.0-dev.5）

转写稿搜索已于 dev.5 采用独立同源 Web Worker，按当前显示的文稿 ID/修订持有快照；查询与定位不增加数据库状态、媒体跳转或主进程能力。当前集的相邻片段视为连续文字，结果仍返回原始片段范围；重叠出现按同一范围合并。取消或修订后不采用旧结果。理由与实际保护证据见[转写稿搜索](TRANSCRIPT_SEARCH.md)。
