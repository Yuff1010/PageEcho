# 按需离线组件安装与版本恢复

入口为“缓存与任务 → 存储与组件 → 本地字幕组件 → 安装与版本管理”；首次字幕生成面板和“收听工具 → 字幕与缓存”使用相同组件。当前没有公开组件更新源，界面明确显示在线源未配置；本地 ZIP 安装与真正的远程下载更新分别验收。

`0.39.0-dev.1` 统一这三个入口。安装面板按“选包 → 核对 → 安装 → 启用”分开动作，离线安装帮助中的包名、版本、设备和 ZIP 大小由 Main 的未撤销可信目录投影，不在界面另写一套版本表。帮助没有在线下载地址，也不代表组件框架全部告警已清除。

附近 `release/` 的 `PageEcho-ASR-*` 与旧 `asr-component-*` 都可浅层发现；仅检查有限根目录和候选，不扫描整盘。路径可选标为“未检查”，选择后仍需检查文件／依赖／设备。候选位置通过说明图标查看，真实失败保持可见。当前配置五分钟内的成功能力检查才用于设备提示；显卡名字和路径存在都不是 CUDA 可用证据，也不会替用户改引擎或设备。

缓存与任务的三个标签只挂载所选面板，键盘切换保持原生 tab 语义；安装活动由 Main 保留，重新打开时只读恢复实际目标和状态，不自动安装或启用。旧版安全门槛、取消、空间检查及历史版本恢复继续由原安装事务执行。

## 使用流程

1. 选择本次安装的引擎和设备，再点“选择本地组件 ZIP”。该目标只控制安装资源和检查能力，不修改书籍的字幕设置。
2. 应用核对固定发行目录中的整包大小、SHA-256、可信清单、ZIP64 结构、目标路径和磁盘余量。核对完成后显示组件版本、预计新增占用及目标盘剩余空间。
3. 点“安装所选组件”。只解压必要模型，保留完整运行库、工具、断句资源及许可证。安装可以取消；成功后检查依赖和所选设备，不自动启用或生成字幕。
4. 在已保留列表点“启用此版本”。应用重新校验所有引用文件并执行能力检查，成功后才替换配置。已有字幕生成、声音对齐或其他维护任务时会拒绝切换，普通播放继续。
5. 之前的外部配置会保留独立恢复记录，点“恢复此版本”重新检查后切回。原外部目录仍需存在，记录不复制其模型或依赖；移动或删除后不能承诺恢复成功。

## 完整性、取消和恢复边界

解压采用 Node 流式读取，不执行 ZIP 内的 Python、安装器或自带配置。除了整包与清单固定摘要，还核对条目长度、SHA-256、CRC、本地/中央目录、路径大小写冲突、链接、范围及文件集合。生成的六字段 v2 配置和模型清单由主程序创建，旧 v1/v2 外部配置继续支持。

资产先写入隔离 staging，完整组原子提交到新 generation，最后才提交安装记录；不覆盖被引用的旧组。取消可能保留已经校验完成的组，下次重新核对后可复用；未提交记录不会作为可启用版本出现。损坏或篡改的组保留原状，安装使用新的组。取消和退出等待所属文件流与检查进程收尾。

托管根为用户数据目录下的 `c/`，资产使用短路径 `a/<包摘要前12位>/<组>/<16位随机标识>`。Windows 安装前计算最终 EXE、DLL、PYD 的绝对路径，超过 240 个字符即明确拒绝，不在写入数 GB 后才尝试加载。外部组件可放在较短目录后通过原来的组件文件夹入口使用。

0.16 dev.1 的真实安装暴露了两个问题：深层 DLL 路径触发 WinError 206，以及读取 v2 安装身份时在记录目录创建了 cache。dev.2 缩短路径并增加提前拒绝检查；身份读取改为使用主应用的缓存目录，安装记录保持四个文件。初轮失败现场、原配置不变的证据及后续重跑均保留。

## 验证状态

最终 0.16.0-dev.4 的 252 项逻辑、12 项 Node 进程与 138 项 Python 检查通过；其中安装相关逻辑覆盖 ZIP64、恶意路径、损坏文件、空间不足、取消与清理、跨引擎复用、CPU 设备限制、路径长度、显式启用、验证先于执行、外部恢复和记录重启。27 项桌面流程通过，包含 3 项新增安装界面检查。

通用包在 dev.2 完整安装 35,462 文件 / 11,805,663,173 字节；CPU 包在 dev.3 完整安装 35,421 文件 / 7,538,047,252 字节。各自执行真实默认预检、单独启用、CPU1 转写与媒体定位、恢复旧配置、重启及全部文件哈希复核。另装 WhisperX 的预览均只需新增 1,621,667,428 字节，未重复解压共享运行库。最终冻结版本对已有资产的兼容复核和完整证据见 [批次验证](OPTIMIZATION_VALIDATION.md)。

独立复核还确认并修复了旧 v1 配置仅缓存目录不同却合并历史的问题。最终身份包括实际缓存路径，两个配置各自保留并可分别恢复；列表显示本地保存时间，真实 v1 回归已通过。

界面故障用例在临时应用副本注入受控 core/probe，保持真实服务、IPC、队列及配置流程；每个用例记录原始与修改后摘要。未知 ZIP 及非法 IPC 的用例使用原生产 core/catalog。夹具不证明真实模型可用，真实模型另用原封冻结预览和完整组件运行。独立安装包、干净设备和远程发布源仍待验收。
