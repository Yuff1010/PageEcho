# 字幕编辑与撤销

此功能已在 `0.18.0-dev.2` 独立预览完成流程验收。先退出旧预览，再双击 `cache/preview-builds/2026-10-24T02-56-44.359Z/start-preview.cmd`。它沿用 0.13 独立预览数据并升级到 schema 14，旧预览不能打开升级后的目录；主 `out/` 保留原构建。证据见 [批次验证](OPTIMIZATION_VALIDATION.md)。

## 操作入口

播放一集已有正式文稿的音频，进入“伴读阅读”，点击“字幕编辑与撤销”；也可点击某句的“编辑”，直接选中这一句。原有“纠错”继续提供小范围文字修改。

编辑面板先预览，再点击“应用字幕修改”。取消预览、关闭面板或模型返回建议均不会自动改写正式文稿。真正保存后，新修订会同步到高亮、搜索和导出；播放器继续使用同一个原音频和媒体时钟。

| 功能         | 操作                                               | 保存规则                                                |
| ------------ | -------------------------------------------------- | ------------------------------------------------------- |
| 文字纠错     | 修改选中句的小范围错字                             | 保留句子 ID 和时间；保留原有小范围修改限制              |
| 拆句         | 填写第几个字符后分割，以及试听确认的原音频整数毫秒 | 两边都需非空；两句各生成新 ID，原句身份保存在撤销历史中 |
| 合句         | 选择相邻两句，直接拼接或加一个空格                 | 新句使用新 ID；只能位于同一个现有覆盖区间               |
| 调整时间     | 选择最多 20 个连续句子，逐句填写起止毫秒           | 检查完整文稿的顺序、邻句、时长和覆盖范围                |
| 名称批量纠错 | 输入原样查找与替换文字，选择本集或本书勾选集       | 预览全部计数，明确应用；整批作为一项历史保存            |
| 按声音重对齐 | 选择句子和 CPU/NVIDIA GPU，生成时间建议            | 使用固定离线对齐模型；通过检查后仍需明确采用            |

所有毫秒都是原音频坐标，不随倍速变化。拆句可以点击“使用当前播放毫秒”填入试听位置，程序不会按字数均分时间。合句不会新增覆盖区间，不能跨过未覆盖区域，也不能把两个单独声明的覆盖区间拼成一个。

## 跨集名称纠错

查找与替换各限 1–100 个 Unicode 码点，不能为空、相同或含控制字符。不使用正则表达式，不自动转换繁简体，不跨句匹配；例如只查找“肖炎”时，不会顺带替换其他写法。预览显示分集、句子和出现次数，逐页核对后点击应用。

本书勾选集可跨目录页选择，每次最多 1,000 集。没有当前音频版本正式稿的集数会明确计为跳过。选中文稿在读取前按数据库记录检查总大小，上限 64 MiB；每批最多修改 10,000 句，完整历史差量最多 2 MiB。超限会要求缩小范围，不会悄悄只处理前一部分。

预览每页 50 句，有效期五分钟。应用时重新核对所有选中正式稿的版本及发起集的版本；任一版本变化时整批拒绝，重新预览后再操作。只保存实际命中的文稿；未命中的集数仍可继续接收其后台字幕。

## 持久撤销与重做

每集最多保留 20 项编辑历史，重启后继续使用。拆句、合句、纠错、手动调时及采用声音建议都可撤销；撤销恢复原来的句子 ID、文字和时间，修订号继续递增。撤销后再做新编辑，会清除相关的重做分支。

跨集纠错整体撤销和重做。若其中一集还有后续编辑，需要先撤销后续操作；若成员已移除、音频改变或重新采用外部文稿，整组会显示不能部分恢复的原因。未命中的发起集后来收到新字幕，不应阻止从实际修改的集数撤销整组。

编辑过的正式稿受人工保护：后台生成可以继续保留结果供预览，但不会自动覆盖人工修改；撤销也不会重新开启自动覆盖。重新导入文稿或明确采用另一份生成稿视为新基线，清除该文稿对应的编辑入口。原文同步点、人工空缺、片段标注、书签及试听校对分别保存；撤销字幕不会回退后来保存的原文人工修改。

拆句、合句会更换结构身份，已有原文映射不能直接继承给新句子；后续匹配需重新核对。旧修订的搜索结果、导出选择、试听校对和声音建议继续按版本检查，不能作为当前修订直接采用。

## 声音重对齐

它以当前字幕文字和实际音频为输入，无需先导入小说原文。每次选择 1–20 个相邻句子，最多 60 秒、1,000 字，必须位于同一个已覆盖区间。纯标点或空白句不能生成时间建议。

显式选择 CPU 或 NVIDIA GPU 后运行本地固定对齐模型，不自动下载模型或改用其他设备。处理暂停时需先恢复；正在运行的转写与声音校准共用模型占用控制。暂停中的离线准备计划若已让出模型，不应阻止手动校准。

模型只生成实验性建议。界面对照当前时间与建议时间，可试听当前范围和建议范围；点击“采用字幕时间建议”后才保存，并可立即撤销。取消或关闭所属面板会停止该次模型子进程并等待退出。普通播放使用原有播放器；关闭试听会停止所属试听。

音频内容、正式稿修订或所选句子变化时，旧建议不可采用。建议时间必须来自实际字符对齐结果，不能通过均分、插值或填补缺失来伪造。沿用原文声学对齐的质量检查与已知限制：公开材料仍有正确参考被拒和内部删字漏检，不能据单条模型流程证明小说同步准确率，见 [声学对齐](ORIGINAL_ACOUSTIC_ALIGNMENT.md)。

## 验证与边界

最终 `0.18.0-dev.2` 的完整代码检查通过，389 项逻辑、12 项 Node 进程、138 项 Python 及 35 个不同桌面用例通过。覆盖 Unicode 字符切点与长度、整书跨页预览、原文人工修改并发、真实 SQLITE_FULL、跨集提交及撤销回滚、20 步历史、重启和 schema 13→14 迁移。

真实 CPU 与 CUDA 主进程分别完成两集纠错、预览取消、整组撤销、重启重做、拆句、观察到实际对齐子进程后取消并等待退出、建议生成、明确采用、媒体点句及精确撤销。报告为 `cache/optimization/transcript-editing-main-dev2-{cpu,cuda}-2026-10-24-final/report.json`，固定公开参考仍为同一条“太平洋商业中心”音频及人工文字；没有导入原文。该样本没有人工时间边界，不能当作声音同步质量验收，也不增加小说听审样本。

首次桌面回归保留 29 通过／4 失败的完整日志与 traces，四项失败均复现“纠错”和“编辑”按钮位置重叠。最终改为三个独立并排按钮，720×600 窗口实际点击三项及矩形无交叠回归通过。补充平面字符的输入框、IPC、纯操作和数据库校验已统一；100 个字符可完整预览并保存，101 个明确拒绝。

部分桌面声学状态与保存响应时序通过临时副本中的固定协议子进程或响应延迟夹具控制，原／改 SHA 与范围均另存；它们不替代上面的真实 CPU/CUDA 模型证据。最终只读审计绑定源码、输出、Python、原 `out/`、运行日志、参考、实际数据库和相关截图，见 `cache/optimization/transcript-editing-final-validation.json`。
